# 示波器（scope）的类型契约

2026-08-30。hml 试用 tap 示波器后决定重做：示波器成为**生产口所在壳体里的一台采集
引擎**（深度到 8 GB、采样率到 100 MS/s、通道数增加降采样率、生产方不自己开窗、超预
算走抽取），tap 退回纯订阅（保留选列），`waveform_chart` 退回看波形。引擎、RPC、线
协议、前端在 sigflow-core `docs/scope.md`（feat/scope）；本文是类型层的契约，落在
sigflow `feat/scope`（从 feat/tap-scope 分出）。`tap-scope.md` 里"触发住在 tap 里"的部
分作废，tap 身份 / 选列 / 线协议 v3 / 按连接过滤保留。

## 1. dtype 与码→物理量（`semantic.rs`、`manifest.rs`）

- `Dtype` 枚举 `i8 | i16 | i32 | f32 | f64`（`elem_bytes`、`is_integer`、`FromStr`）；
  `SemanticType.dtype` 仍是字符串，但只能是这五个名字之一，**没写 = f32**
  （`SemanticType::dtype()`，不认识的名字是错、不猜）。
- `ColumnDecl.scale` / `offset`（缺省 1 / 0）：`物理量 = 码 × scale + offset`。
  `unit`/`bound` 指物理量；`decode`/`bits` 作用在**码**上。
- 连线规则（sigflow-core 的 connect 校验）：生产口 dtype 是整数时，消费口必须显式声明
  同一 dtype；消费口没写 dtype = 只收 f32/f64。理由：今天的消费方都按浮点读样本，
  收到 i16 就是静默读错。
- tap 对整数口按 scale/offset 换成物理量 f32 再发（线协议不变）；示波器按原生 dtype
  存，视图/测量时才换算——示波器不制造分辨率。

## 2. 协商（`PortDescriptor.negotiable`）

```toml
[[ports]]
id = "adc"
negotiable = { rate_param = "fs_hz" }
```

- `rate_param`：f64 Hz 的 hot_change 参数。消费方（示波器 / 录制器）写它请求的率；生
  产方就近取自己支持的率，**回读值 = 接受的率**，并且**每一帧带 `sfrate01` 注解**说实
  际率——帧是证人，回读只是应答。
- 声明了 `negotiable` 的口**不得**声明 `declared_rate_hz`（`PortDescriptor::validate`）：
  那条只给编译期常量，协商口的率是运行时的。
- 降率只许峰值检测（`FLAG_PEAK_PAIRS`）或均值，**不许丢样本抽取**——那是混叠。SDK 的
  `Decimator` 助手二期随第一个实现 `rate_param` 的生产方一起做。
- 选列协商（生产方只算、只发子集）**这一轮不定**：帧只有一个注解槽（`[schema_id |
  bytes]`），子集会让帧的列布局和契约分家，要有带列表的流注解（rate + cols 合一个
  schema）才能做——二期定。一期的预算只靠 `rate_param` + 入口抽取。

## 3. `FLAG_PEAK_PAIRS`（`frame.rs`，bit3）

每 scan 每列 `(min, max)` 交织，`n_samples` 计的是 scan 数（对数），payload =
`n_samples × 列数 × 2 × elem`；率（declared 或 sfrate01）是抽取后的率。只在生产方响应
协商时出现，所以：声明了 `negotiable` 的口，其消费方必须认这个标记——示波器按对存，
tap 作为 `TAP_FLAG_PEAK_PAIRS` 传下去、图画 min/max 竖条，**不许只取一半**。非 signal
列（enum / bitfield / counter）的对也是 `(min, max)`，两者不等 = 这一 bin 里变过。

## 4. `ScopeConfig`（`ui.rs`，持久化在 `WidgetBinding.scope`）

TOML 形状在 `ScopeConfig` 的文档注释里。要点：

- `channels`（空 = 整口）、`depth_bytes`（> 0，上限归壳体环境变量）、
  `budget_bytes_per_s`（缺省 400 MB/s；**按存储字节算**——峰值存储每 scan 一对，
  `D = ceil(2 × fs_native × Σbytes / budget)`）、`refresh_hz`。
- `timebase`：`span_s` 或 `span_scans` 二选一必填；`position ∈ [0,1]` 缺省 0.5 = 触发点
  在屏幕的位置——它是时基（水平位置旋钮），不是触发的属性，`ScopeTrigger` 里没有。
- `ScopeTrigger` = 原 TapTrigger 去掉 position、加 `kind: edge | pulse | window`（一期只
  实现 edge；pulse / window 的参数二期加可选字段）。状态机语义同前（迟滞、释抑按拍、
  NaN 透明、断清连续段、触发拍算 post 第一拍），加亚采样相位 `frac`；峰值存储时
  rising 在 max 平面、falling 在 min 平面。
- `acq`：`normal | average | persist`；`average_n ≥ 2` 且 average 必须有触发；
  `persist_decay ∈ [0,1]`，**1 = 不衰减**（没有 "inf"）。
- `vertical[]`：逐通道 `v_div > 0`、`offset`、`on`、`coupling dc|ac`、`interp
  none|linear|sinc`、`bw_limit_hz ≥ 0`；`channel` 必须在 `channels` 里（空 = 整口时不
  查）。AC = 减去当前记录窗内的均值，密度 / 视图 / 测量都按耦合后的值。
- `measure`：`channels ⊆ channels`、`gate screen|cursors`；`gate = cursors` 时
  `cursors = { a, b }` 必须给（相对时间零点的存储拍数，可为负，a ≠ b）——光标是
  setup 的一部分，UI 拖光标即时 `scope_set`、手势结束回写；引擎不会拿屏幕代替。
  测量在引擎里按记录算，随 meas 帧发，不适用 = NaN 不是 0。
- **`ColumnRef` 的相等是"写法相等"，不是"指同一列"**：单组口上 `{ column = "v" }`
  （每组）与 `{ column = "v", group = 0 }`（第 0 组）指着同一路，`PartialEq` 却判不
  等。拿它当 map 键 / 做集合比较的代码要**先落到具体通道**（交织下标，或 (列 id, 组)
  一对）再比——sigflow-core 的触发源下拉曾整个显示为空，就是 CLI 写 `0/v`、控件按形
  状省成 `v`，两边按写法取键对不上（c079449 修）。类型侧 `selected_in` 的方向也记在
  它的文档注释里：`sel` 里不带组序的覆盖该列所有组，反过来不成立。
- **拍数的度量**：`timebase.span_scans` 与 `trigger.holdoff_samples` 都是**源口的拍**
  （抽取前）；入口峰值检测 D:1 之后引擎自己除以 D 换成存储拍，操作者不用知道 D。
  `measure.cursors` 相对时间零点，按**存储拍**计（它是视图坐标）。
- 几何（改了重建环）= `channels + depth_bytes + budget_bytes_per_s`；其余就地。
- `TapConfig` 去掉 `trigger`（旧绑定里的 trigger 字段读时被丢，不报错——它只存在于没
  合过的分支上）；`TapTrigger` 类型删除，`TrigSlope` / `TrigMode` 保留给 ScopeTrigger。
- 一个口绑定要么 `tap` 要么 `scope`，按控件类型二选一。CLI：
  `widget bind <alias> port:<id> --scope-file setup.toml`；壳体 `widget_bind` 对本节点口
  当场解析列 id（同 tap 那条）。

### 4.1 引擎落地时核过的几条（sigflow-core 92868fd）

- 外触发源不在选中列里时追加进环（环列 = 显示列 + 触发源列）；vertical / measure 按
  （列 id, 组）身份配对；率取 sfrate01 > declared_rate_hz；`span_s` 而口无率 → 拒。
- `D = ceil(fs × 存储字节/scan / budget)`，源已是对时字节本来翻倍、不再乘 2。
- 视图帧的 `kind` 加了 2 = 原始 (min, max) 对（对存储放大到每像素不足一拍时）。
- 口在对 / 非对之间切换而环布局不合（decim = 1）时帧被丢并计入 `dropped_scans`
  ——不会静默按错布局写。
- **view 帧的横坐标约定**（hml 第二轮试用报的"电平、触发位置、波形不交于一点"，
  sigflow-core f63e466）：`kind = 1 / 2`（原始样本 / 原始 (min,max) 对）里第 j 个在
  **拍坐标 `x0 + j`** 上，不是"第 j 格的格心"；`kind = 0`（每像素列 min/max）第 i 列
  覆盖 `[x0 + span·i/px, x0 + span·(i+1)/px)`，画在**列心**。两种约定混用（把样本
  当格）会让波形整体比触发点右移半拍——T 标记画在整拍位置 `ref_abs`，一屏只有几
  十拍时半拍就是几十像素（实测 20 拍一屏 / 1177 px 时 28 px）。台阶插值
  （`interp = none`）保持到下一拍（ZOH），跳变画在样本自己那一拍上，与触发点同处。
- **触发点钉住**（hml 试用反馈，sigflow-core 4ae9479）：触发窗的时间零点是
  `ref_abs − 1 + frac`（跨越点在两拍之间）。T 标记钉在 `ref_abs` 那一列，**波形、密度
  累积、光标读数一律整体右挪 `1 − frac` 拍**，各窗的跨越点才叠在同一像素列上（时基越
  小一拍占的像素越多，不挪就左右抖）。`measure.cursors` 仍按相对 `ref_abs` 的整数存
  储拍存，显示与读数按挪过的位置取。
- **余辉跟着通道的插值方式走**（hml 第三轮试用，c079449）：密度累积在壳体、矢量线在
  前端，原来密度恒按两拍连线，选了台阶 / sinc 后同一条波在余辉里和矢量线上形状不
  一样。现在 `VerticalSetting.interp` 一并传进密度累积（引擎内部字段，线协议不动）：
  样本级放大时列是两个边界值之间的一段，边界按 interp 算——`none` 取所在拍（跳变列
  自带竖线，与 ZOH 矢量线同处）、`linear` 两拍连线、`sinc` 8 抽头 Lanczos（权重查
  表，256 档亚拍位置，与前端同样归一化、同样夹边界）。`interp` 变了和 `v_div`/
  `offset` 一样清计数。
- 密度图放大到样本级：列数下限 1024（不再 = span），每列在两拍之间线性插值取列两端
  的 min/max——相邻样本连成斜段而不是一拍宽的台阶块；每个采集 tick 最多累 512 窗
  （超了抽着累，形状不变）。实测 1 MS/s 正弦 5 µs/div、触发 1 万/s 仍 30 帧、壳体
  12% CPU。
- `scope_state {scope_id}` → `{state}`：只拿运行态（触发/s、丢拍、写指针），控件按秒
  轮询状态行用；view 帧只带 flags，触发率不随帧走。
- view 帧每通道带 `ac_mean f32`（`[ch u32][kind u8][ac_mean f32][n u32][f32 × n]`，DC 为
  0）：AC 耦合时引擎从样本里减掉的均值只有引擎知道，控件用它把电平线画在
  `level − ac_mean`、拖电平时把均值加回去再 `scope_set`，光标处的通道读数也按它
  算（sigflow-core 47c6c41 落地）。
- 单列多组的色相规则住在 `traceColor(col, group, groups, ncols)`：`ncols === 1` 且
  `1 < groups ≤ 8` → 每路一个色相，与单组时第 group 列同色；waveform_chart 与
  oscilloscope 都经它取色（47c6c41）。

## 6. 测试源 `plugins/native/sig-gen`（sigflow 仓，原生插件都在这里）

一期：`fs`（改它 = 新采样轴 = 断）、`channels`、`dtype i16|f32|both`、每通道波形
正弦 / 方波 / 三角 / 脉冲 / 噪声、幅值 / 频率 / 占空 / 相位、注入跳号的 action；**不声明
`negotiable`**（协商二期），超预算时靠它验入口抽取。验收与压测（100 MS/s、8 GB）都以
它为源，不依赖 dex 仿真能否连续实时。

`dtype = "both"` 是**多源示波器的验收源**：两个口同时发、各自一个率（f32 走 `fs_hz`、
i16 走 `fs2_hz`），一个节点上就凑得出两个不同率的源进同一台示波器（跨节点是 12-b）。
两条流锚在同一时刻、同一相位，相位每拍推进 `freq/fs`，所以在**绝对时间**上是同一根
信号——重采样到同一根时钟之后同一拍上两路该读到同一个值，差多少就是对齐误差
（§8.4 量到 3.9e-5 = i16 的量化底）。多流化的代价：同机同日 f32×4 聚合从 977 M
样本/s 掉到 904 M（≈ 7%），仍是 100 MS/s 需求的两倍以上。

## 6.1 验收记录（sigflow-core feat/scope a4a5c67 + sig-gen 5b71dfa，release，假 HOME/9502，i7 级桌面）

- ✅ 单通道 i16 100 MS/s、8 GB 深度、连续 60 s：入环 100.0 MS/s 稳、丢拍 0；1 MHz 正弦
  上沿触发 10 万次/s（受 pre+post 重臂限）；环文件 6.46 GB（预算减金字塔）在 /dev/shm；
  采集线程 ≈ 0.8 核；20 亿拍全景视图 RPC 5 ms、8 亿拍 2 ms。
- ✅ 1 MS/s × 2 ch f32、10 kHz、normal 触发 + persist：view 20 Hz、density 两通道、meas
  freq 10000.0 / period 100.0 µs；触发在窗中点、frac 1.000（10 kHz @ 1 MS/s 正好采到
  0）；分段 256 条；stop / single / 回翻 / set 不重建 / 改深度重建全过。
- ✅ 4 ch f32 100 MS/s（1.6 GB/s → 8:1 峰值检测存 12.5 MS/s）：sigflow-core 1961b9e 之后
  存 12.5 MS/s 稳、丢拍 0、触发 10 万/s；入环线程 68%、采集线程 49%、处理线程 19%。
  之前只到 20.7 MS/s 的原因**不是生成也不是入环的算力**（sig-gen 纯生成 f32×4 正弦
  1054 M 样本/s ≈ 0.95 ns/样本；RingWriter 8:1 抽取 528 → 向量化后 676 MS/s），而是壳体
  两条结构限制，已改：插件输出缓冲原来固定 1 MiB 不看 `max_frame_bytes`（现在按声明
  开，只增不减）；源节点 tick 原来是"干完再 sleep 1 ms"（现在固定 1 kHz interval）。
  改完 87 MS/s（处理线程上生成 + 抽取 ≈ 1.14 核卡住），再把入口抽取挪出处理线程
  （feed 只 memcpy 进 64 MiB 有界暂存队列，独立入环线程抽列/抽取/写环，采集线程只做
  金字塔/触发/密度/推帧）才到 100。没连消费方时壳体不发布（`has_publisher` 为假直接
  跳过），没有共享内存的白拷贝。

## 9. 率与深度是推导出来的（2026-09-01，hml 提的方向）

出处：hml 试用后要求"**采样率和存储深度不是设死的，是时基、深度档、通道数算出来
的**——真示波器就这样，我们现在这套更像数据记录仪"（由 sigflow-core-03 转述）。

### 9.1 控制律（壳体实现，类型层只定输入）

```text
窗口时间   = timebase.span_s                  （**一屏**；屏上十格，s/div = span_s / 10）
每通道深度 = floor(depth.points / 通道数)
fs         = min( clock.fs_max_hz / 通道数,                  ← 通道交织，不取档
                  1-2.5-5 向下取档( 每通道深度 / 窗口时间 ),  ← 只有这一路取档
                  源的率 )
存储点数   = 窗口时间 × fs                     （≤ 每通道深度）
```

1 GSa/s、深度 100 M、单通道：1 ns/div → 率撞上限、一屏只存 10 点；10 ms/div → 正好
占满 100 M；20 ms/div → 500 MSa/s；30 ms/div → 333.3 MSa/s 向下取到 **250 MSa/s、
存 75 M**。

**阶梯是 1-2.5-5，不是 1-2-5**（2026-09-01 hml 定，知道两边代价后选的）：真机的采样率
表就是 100 M / 250 M / 500 M / 1 G，**减半必须落在档上**（1 G 的四分之一是 250 M，
1-2-5 会给 200 M）；同一时基下也更省深度（75 M vs 60 M）。他早先口述的"30 ms/div →
200 MSa/s、存 60 M"是按 1-2-5 心算的，以本节为准。时基旋钮仍是 1-2-5——**两个旋钮
不是同一套阶梯**，别顺手统一。

**取档只作用在"每通道深度 / 窗口"那一路**（sigflow-core 4362609 定的，我同意）：
`fs_max / 通道数` 是 ADC 真交织出来的数，1 GSa/s 的八通道就是 125 MSa/s——它本来就
不在档上，对 `min` 的结果取档会把它削到 100 MSa/s，凭空少两成。源的率同理。

**控制律只有一份，在壳体里**（`scope/horizontal.rs`）。前端不许自己算一份——率和
深度都从引擎的状态里读。两份实现迟早对不上，那时屏幕上写的和环里的不是一个数。

**推导的输入只许是声明**（时基、深度、通道数、`fs_max_hz`）**加已经稳定的观测**
（源的率）；观测那一项要跟环一起记住，认领时重算得同一个数才不清环——第一个观众
到场清掉常驻示波器攒的一切，就是 §8.5 修过的那个 bug 换个入口再来一次。

### 9.2 类型层（`ui.rs`，我定的形状）

- **`ScopeDepth { max_points, points }` 换掉 `depth_bytes`**：按**采样点**算（仪器上
  写的是 100 Mpts 不是 400 MB）。`points` 是所有通道合计，`per_channel(n) =
  points/n`；`points` 省略 = 用满 `max_points`。
  **深度档存的是点数本身，不是档序号**——档序号的含义是一条公式，公式在控件和壳体
  里各写一份就会悄悄对不上；档位阶梯（十分之一、1-2-5、随便）是控件的事。
- **`ScopeClock` 三种模式，`auto` 是缺省**：`auto`（按控制律推导）| `fixed { fs_hz }`
  （钉死，**必须给 fs_hz**——原来"省略 = 取各源最快的率"作废）| `native`（跟源、
  原生 dtype、峰值对，抓 1 拍毛刺只能走它，只能一个源）。
- **`ScopeClock.fs_max_hz`**：这台仪器的最大率（实际 = `fs_max / 通道数`，真机上通道
  共用 ADC）。省略 = 壳体上限，同 `depth` 的字节上限一个分工。
- **`ScopeClock.dtype`**（`f32` 缺省 | `i16`）：`i16` 的量化标度 = `v_div × 5 / 32767`、
  零点 = 通道的 `offset`（屏幕 8 格、存 ±5 格留一圈余量）。代价写在
  [`VerticalSetting`] 上：**`v_div` / `offset` 不再只是画法，改了要清环**。
  **i16 下量程不许自适应**——没写 `vertical` 的通道取列 `bound` 满量程 / 8 格、没有
  `bound` 就 1.0/格（都是声明）；拿首帧观测自适应会在第一个观众到场时清掉攒的一切。
- **`budget_bytes_per_s` 只对 `native` 有意义了**（它驱动入口抽取）：`auto`/`fixed`
  下 `通道数 × fs × 位宽 ≡ fs_max × 位宽`，吞吐已经被 `fs_max` 封住。
- **`auto` 下 `timebase.span_scans` 不许用**：律子按时间推率，拍数会绕成循环
  （窗口 = 拍数/fs，而 fs 又要看窗口）。没有率的口用 `native` + `span_scans`。
- **多源 / 触发源的判据从"是不是 fixed"改成"是不是重采样"**（`auto` 也是重采样）：
  多源要 `auto` 或 `fixed`；这两种下触发源必须在选列里（环里只有选中的列），不想看
  就 `vertical.on = false`——**外触发只在 `native` 成立**。

### 9.3 重建、清环、什么都不做

三件事要分清（混一起就会该保的没保、该清的没清）：

| 变了什么 | 后果 |
|---|---|
| `clock` 模式 / `channels`·`sources` / `depth` / `budget` | **重建环**（重新分配，数据丢） |
| 推导出来的 fs（时基跨了档、通道数变了）、i16 的量化标度（`v_div`/`offset`） | **清环**（分配不动，数据丢） |
| 同一档内微调时基、`refresh_hz`、光标、测量、`on`、颜色 | 什么都不做 |

比真机"动一下就清"省，而且没有正确性损失：环里的数据只要是同一个率、同一个标度采
的，就还是对的。

### 9.4 老 setup 不许拖住节点起不来

`ScopeConfig.depth` 是必填，所以还带 `depth_bytes` 的 node.toml 会在 serde 那层就
`missing field depth` ——**整个子节点起不来，数据面跟着没了**（sigflow-core 在验收图
上真撞到了）。这跟 §8.5 定的"不该因为一个调试用的示波器声明拖住数据面"是同一笔账，
只是发生在类型层接不住的地方。**定的是：`WidgetBinding.scope` 宽容反序列化**——解析
不了就把这份绑定标成坏的、大声报错（`scope_list.failed` 里带文件、控件 alias、
serde 的原话），节点照常起。

不选"给 `depth` 一个 serde 缺省"的理由：深度现在是**推导采样率的输入**，默认一个深度
就是默认一个采样率，操作者看到的是一台"自己变了率"的示波器——把不正常换成正常。宽容
反序列化则对**将来所有**破坏性改动都成立，不只这一次。

**类型层的形状**（sigflow `feat/scope`，已落）：`WidgetBinding.scope` 的类型从
`Option<ScopeConfig>` 变成 `Option<ScopeSetup>`：

```rust
pub enum ScopeSetup {
    Ok(Box<ScopeConfig>),
    Broken { raw: serde_json::Value, error: String },   // 原样留着 + serde 的原话
}
```

反序列化先接成通用值（这一步不会失败）再试着解析成配置，失败就留 `Broken`；序列化时
`Broken` **把原值一字不改写回去**。拿配置用 `WidgetBinding::scope_config()`（坏的返回
`None`——坏的绝不能被当成配置用），拿原话用 `scope_error()`，判断用 `scope_is_broken()`。
TS 那边仍是 `scope?: ScopeConfig`（健康形状），"这台是坏的"走 `scope_list.failed`。

**宽容读不许变成有损写**（这是宽容方案自带的坑）：坏掉的那份绑定必须**原样留在
node.toml 里**，控件在用户明确重设之前**不许回写**——否则控件用缺省 setup 起来、用户
拨一下旋钮，就把原来那份（源、触发、垂直全在里面）覆盖掉了。丢配置比起不来更糟：起
不来看得见，覆盖看不见。

真正发布之后，破坏性改动要走版本与迁移（`scope.version` + 升级），宽容只是"还没发布、
先别让人卡在启动上"的兜底。

### 9.4b 率变了要真的清掉（不是记个断）

`clock` 推出新率之后，环里旧率的样本**必须够不着**。sigflow-core 一度把"清环"实现成
"记个断 + 按新率重锚"——断标了、数据还在、还读得到，于是骑在分界上的视图把旧率的样本
摆在新率的时间轴上：那一段的时间刻度差一倍，频率与周期读数全错。**按"只看一屏"的语
义这不是边角**：改完时基之后的整整一屏都骑在分界上。

已修（sigflow-core 432c6e5）：`valid_from` 水位抬到当前写指针，水位以下当没有——视图、
自由跑切段、触发的连续段起点四处都从水位起。抹 8 GB 字节太贵也跟写方抢，抬水位便宜
且不碰并发。**分段一并作废**：段是按旧率录的，翻页重放会以同样的方式错，而分段翻页
现在是看历史的唯一入口。

这条和 `segment_view` 那个坑是同一条边界的两个方向：一个把合法的越界夹掉了（翻页翻
不动），一个把不合法的跨界放行了（跨率读到旧数据）。**边界要两边都写清楚谁能过。**

### 9.5 存储的单位是一屏（hml 纠的）

**示波器的深度是把这一屏做深，不是留更长的过去**——能随便往回翻的是记录仪，两种仪器
别混。所以 `scope_view` 夹在当前这一屏里，看更早的走分段（每条触发记录一段）。

**Stop 之后也只看这一屏**（2026-09-01 hml 定的，知道代价后选的）：屏内可以放大，看更
早的**一律走分段翻页**。所以 `scope_view` 夹在当前屏是对的，运行时停下来都一样。

代价与随之而来的一条：**分段翻页现在是看历史的唯一入口**，二期的排期要提前。而且
——**自由跑（没有触发）时没有分段，攒下来的就翻不到**。这跟"常驻示波器没人看也在攒"
（§8.5）合起来会变成一句空话：攒了一小时，一个入口也没有。建议（交 sigflow-core
权衡）：**自由跑时也切分段**，按屏长切，每满一屏落一条记录——这样两条决定才自洽，
深度在自由跑下才有意义，而且用的是同一套翻页 UI，不多一个概念。

已落（432c6e5），但**roll 模式漏了**：切段的条件写成 `!roll`，而一屏长过
`roll_threshold_s`（缺省 0.5 s）就是 roll。实测（sigflow-core 432c6e5）一屏 0.5 s 切
得出（16 屏 = 16 段），1 s / 2 s / 5 s 跑满 9 屏一段都没有。**慢扫正是最需要看历史
的那一档**（一屏几秒、环里存着几十分钟），也正是"只看一屏"把过去挡得最死的那一档。
roll 只是"屏跟着写指针走"，不是"不必留记录"——该照切。

### 9.7 自由跑 + persist 今天没有余辉——实现漏了，不是这一档本来就没有

**症状**（sigflow-core 在 example/oscilloscope-music.sh 那张图上量的，触发关着、
`acq.mode = persist`）：同一个「余辉」开关，**X-Y 下有效**（余辉层亮像素 1710，在
累），**切回 Y-T 什么也不做**（引擎压根不送密度帧，矢量线还是满亮度）。

**机制**（我核的代码，sigflow-core main `scope/engine.rs`）：`new_records` 只从触发
扫描器来（`if let Some(s) = &mut scanner`），而**自由跑的分段落在一个完全独立的分支
里**（`if scanner.is_none() && span > 0`，:1262）。密度累加挂在前者那个循环上
（`if persist && ri % accum_stride == 0`，:1295）。于是自由跑的记录接上了**分段翻页**、
**没接上密度累加**。

**定性：这是实现和契约分家，不是"某一档没有这个功能"。** `AcqMode::Persist` 的契约
文字一直是"**每条记录**都进余辉密度图"，而 §9.5 落地之后（432c6e5）"记录"就有了第二
个来源——自由跑按屏长切出来的那些。**新增了一个记录来源，却只接上了当时想着的那个
消费者**；没人回头问一句"还有谁在消费记录"。这跟 §13.7 那族是邻居：那条是"语义变了
要换键名"，这条是"**来源多了一个，要把消费者数一遍**"。

**已修（sigflow-core 5c3220e）**：自由跑那个分支落分段的同时也喂密度，抽稀沿用
`MAX_ACCUM_PER_TICK`（快扫一 tick 可能切出上万屏，**形状靠的是累够多少条、不是累
全**，全累会把采集线程拖死）。

我在示波器音乐那张图上做了四格对照，数的是**引擎送不送密度帧**（0x11）：

| | `acq = normal` | `acq = persist` |
|---|---|---|
| main 0835522（改之前） | 0 | **0** |
| 5c3220e（改之后） | 0 | **294 / 4 s** |

`normal` 那一列两边都是 0——判据分得开，不是"改完什么都多了"；`triggers = 0` 印证
确实是自由跑。

**一个不对称，写文案时别把两条路当成一件事**（core 提的）：引擎这一路累的是**按屏长
连续铺满**的记录，覆盖 100%；X-Y 那张前端画布累的只是**推出去的帧**，所以才需要那个
覆盖率读数。同一个词「余辉」，两条路的完备性不一样——Y-T 那边不需要"覆盖调到最大"，
它本来就满。

**性质变了才值得现在提**：X-Y 余辉做出来之前，这是"Y-T 自由跑没余辉"，一档缺功能；
做出来之后，它变成**同一个按钮在两种画法下表现不一样**——而用户没有任何办法知道为
什么。前者可以排期，后者是每天都在骗人。

### 9.6 迁移

`depth_bytes` 没了，所有 setup 文件都要改成 `depth = { max_points = … }`；缺省时钟从
`native` 变成 `auto`，所以**原来不写 `clock` 的 setup 行为变了**（尤其配 `span_scans`
的会直接被拒）。这是一期内的破坏性改动，趁没合没装先改干净。

dex 的 `foc-sil.sh` 两台已经改完（dex `feat/foc-sil` 953f875）：`osc_loop` 加
`depth = { max_points = 50000000 }`、时钟留缺省 `auto`；**`osc_enc` 钉 `native` +
`span_scans` 不动**——`rotor` 口**没有 `declared_rate_hz`**（200 Hz 是运行期参数
`rotor_hz`），正落在"没有率的口用 native + span_scans"这条上，顺带把外触发（`z` 不进
选列）也保住了。我原先建议它改 `span_s` 是**记错了 rotor 声明过率**，dex 核了 manifest
纠正的——挑口的时钟前先看 manifest 有没有 `declared_rate_hz`，别照记忆。

## 8. 固定时钟与多源（2026-09-01）

出处：hml 试用后要求"示波器有自己的采样率、任何率/任何位宽的源都重采样到这根时钟
上、所有口的所有通道能进同一台示波器，8 MS/s 够用"——**由 sigflow-core-03 转述，hml
本人没在我这会话说过**。引擎侧设计（重采样核、混合写环、跨节点 attach、代价）在
sigflow-core `docs/scope.md` §12；本节是类型层的落地。

### 8.1 落了什么（`ui.rs`）

- `ScopeClock { mode: native | fixed, fs_hz: Option<f64> }`，`ScopeConfig.clock`。
  `native` = 现状（跟着唯一的源走、原生 dtype、整数抽取 + 峰值对，100 MS/s 抓 1 拍
  毛刺那条路留着）；`fixed` = 示波器自己的时钟，各源重采样上来，每 scan 每列一个值。
  `fs_hz` 省略 = auto。**进 `same_geometry`**。
- `ScopeSource { name, node, port, channels }`，`ScopeConfig.sources`。`node` 省略 = 挂
  控件的那个节点；`channels` 空 = 整口。老的 `ScopeConfig.channels` 留作**单源简写**
  （源 = 绑定的那个口），两者互斥。
- `ChanRef { source: Option<String>, #[serde(flatten)] column: ColumnRef }`：
  `trigger.source`、`vertical[].channel`、`measure.channels` 的类型从 `ColumnRef` 换成
  它。摊平序列化 → **老 setup 一字不改照旧能读**（`source = { column = "z" }`），
  TOML 写回也验过（`多源_setup_能写回_toml_再读回来`）。文本形式 `源:列`，
  如 `foc/rotor:0/theta`。
- 解析入口 `ScopeConfig::resolve(&ChanRef) -> (源槽位, &ColumnRef)`，配套
  `source_count` / `source_names` / `channels_of(slot)`。

### 8.2 我改了提案的哪几条，为什么

1. **源引用按名字，不按 `sources` 下标**（提案是 `source: Option<u32>`）。下标是位置：
   中间插一个源、删一个源，所有引用会**悄悄**指到另一路去——那正是"口加一列就错位"
   这笔账（§4 `ColumnRef` 那条）。名字错了 validate 当场报。缺省名 = `port`，给了
   `node` 就是 `node/port`；重名要求写 `name`，名字里不许有 `:`。
2. **两个以上源时省略 `source` 是错，不是"取第 0 个"**。猜错了就是量错一路，而这一路
   在屏幕上和量对了长得一模一样。只有一个源时可以省。
3. **`fs_hz` 的上限归壳体**（`SIGFLOW_SCOPE_MAX_FS`，缺省 8e6），类型层只查有限且
   > 0——和 `depth_bytes` 同一分工，类型层不该知道某台机器的环境变量。
   `mode = native` 时给 `fs_hz` 是错（写的人以为它有用）。
4. **`fixed` 下触发源必须在选列里**。`native` 的外触发成立是因为写环时读整行；`fixed`
   下环里只有选中的列，没进环就不在共同网格上，触发无处可跑。validate 拦。
5. **拍的度量跟着时钟走**（提案没说，会当场差一个 D）：`span_scans`、
   `holdoff_samples`、`CursorPair` 在 `native` 下是**源口的拍**（引擎自己 /D），在
   `fixed` 下是**示波器时钟的拍**（没有 D，不换算）。
6. **`fixed` 环一期恒 f32**。§12.1 提的"可选 i16 换深度"没进类型层：i16 存重采样后的
   物理量需要一个量化标度，标度从哪来（列 `bound`？每通道 full-scale？）是个决定，
   不是个字段。定了再加 `clock.dtype`，二期。

### 8.3 校验规则（`ScopeConfig::validate`）

`channels` 与 `sources` 二选一；每个 source 的 `port` 非空、`node`/`name` 给了就非空、
解析名唯一且不含 `:`；两个以上源要 `clock.mode = fixed`；`native` 不接受 `fs_hz`，
`fs_hz` 给了要有限且 > 0；`trigger.source`/`vertical[].channel`/`measure.channels` 都要
能 `resolve` 到一个源，且（除 `native` 的外触发外）在该源的选列里。

列 id 存不存在、节点/口在不在图上、`fs_hz` 与 `depth_bytes` 超不超本机上限、无率口在
`fixed` 下拒绝入环、停摆源填 NaN 标 missing——都到壳体才知道，归引擎。

### 8.4 多源真图验收（2026-09-01，sigflow-core 6d38b5c + sig-gen 两口同发，release，假 HOME/9502）

一个 sig-gen 节点两个口（f32 1 MS/s + i16 250 kS/s，绝对时间上同一根 1 kHz 正弦、
幅度 0.9）进同一台固定时钟 500 kS/s 的示波器：

- ✅ **对齐**：同一拍上两路最大差 **3.9e-5**（rms 2.0e-5）——就是 i16 的量化底
  （1/32768 = 3.1e-5），不是对齐误差。频率量到 1000.0 Hz。2 s 写指针 999983 拍
  = 正好跟上实时，丢拍 0。
- ✅ **停摆**：把 i16 口停掉（`dtype` both → f32），1.5 s 写指针照走 752035 拍
  （= 实时），停摆那一路 1000/1000 拍是 NaN、**0 拍是 0**；恢复后那一路回来，
  两路差仍是 3.9e-5。
- ✅ **大抽取比**（1 MS/s → 10 kS/s = 100:1）：带内 1 kHz 出来 0.896，带外 12 kHz
  （新奈奎斯特的 2.4 倍）残量 **5e-6**。
- ✅ **口的归属**：口名打错、源里写别的节点的口，都当场报并指路。
- ❌ **发现的问题**：抽取比一大就丢拍——ratio 2 丢 0、ratio 10 丢 4%、ratio 100 丢
  **65%**，且环跟不上实时。原因不在滤波器的算力，在 `Resampler::retune()`
  **每帧都建一张多相表再扔掉**（`kernel()` 先 `Poly::new()` 再比抽头数）。实测建
  一张表：32 抽头 0.47 ms、160 抽头 2.3 ms、800 抽头 11.2 ms、1024 抽头 14.4 ms
  ——按 1 kHz 的帧率就是 0.47 / 2.3 / 11 / 14 个核，全花在建了就扔上。已提
  sigflow-core：先算形状（抽头数 + 截止 + 预抽取比），变了才建表。

引擎级测试盖不到这条：那里的 `t0_ns` 是完美等间隔的，拟合出的率不抖、每帧走的是
同一个形状；真图上帧到得有抖动，形状每帧都要重算。**验收要在真图上做**，这是第三
次（前两次是 1 MiB 输出缓冲、sleep 1 ms 的源 tick）。

**复测（sigflow-core 9bc27e4，改成"先算形状、变了才建表" + 抽取比按 5% 等比阶梯向上
量化 + 2.5% 迟滞）**：三档比（1 MS/s → 500 k / 100 k / 10 kS/s）丢拍全 0、写指针全部
正好跟上实时；多源对齐仍是 3.9e-5、停摆仍是 1000/1000 拍 NaN。

**顺带量出固定时钟的通带形状**（1 MS/s → 10 kS/s，幅度按 rms×√2 量——用 max 会被采样
格点拖低，2.5 kHz 在 10 kS/s 上一周期才 4 个点）：

| 频率（× 新奈奎斯特） | 0.05 | 0.2 | 0.5 | 0.8 | 0.9 | 2.4 |
|---|---|---|---|---|---|---|
| 出来的幅度 / 真值 | 100.0% | 100.0% | 100.0% | 93.8% | 73.1% | 0.0% |

正常的抗混叠滤波器形状，但**对示波器是个要说清的事**：固定时钟下能照实读幅度的带宽
只到 **0.8 × 新奈奎斯特**（≈ `fs/2.5`），再往上是滤波器的滚降不是信号变小。要量某个
频率的峰峰值，时钟至少取它的 2.5 倍；抓毛刺仍然只能走 `clock = native`。

**NaN 有两条完全不同的路，别把它们当一件事**（2026-09-02，dex 问的，sigflow-core
核实并补了测试 `44b473b`）。上面那条验收量的是"整路停摆 1000/1000 拍 NaN"，那只是其
中一条：

| NaN 从哪来 | 走哪条路 | 在屏上多宽 |
|---|---|---|
| **一路停摆**（源不出数了） | `RingWriter::fill_nan_to` **直接写环，压根不过重采样** | 停摆多久就多宽，10 ms 就是 10 ms |
| **源数据里自带一个 NaN** | 过重采样核 | `Band` 正好晕开 **`TAPS_UP` = 16 个源样本**（±8）；`Zoh` 只晕 1 个 |

dex 问的是"10 ms 的停摆会不会被读成 90 ms"——**不会**，因为停摆走的是第一条路。但第
二条路是真的：他那台 200 Hz 的 rotor 上，**一个** NaN 源样本在屏上是 **80 ms** 宽的
空洞，跟他一屏 50 ms 同量级。

**晕开是对的，不是 bug**：带限重建要用缺失样本周围一整个窗，那个窗里的输出本来就不
可知；把它收窄成一个点，等于在洞上编中间值。要点是**这件事既没文档也没测试**，而
§8.4 那条验收盖不到它——**两件事，一件有网一件没有**，而它们共用"NaN"这一个词（又是
§13.7 那族：一个词两个所指）。

### 8.5 示波器的寿命：会话的 vs 节点的（2026-09-01，hml 拍板）

现状是**一台示波器跟着开它的那个 WebSocket 连接走**：连接一断壳体就替它
`scope_remove`（跟 tap 一套——8 GB 的环不能靠 GC 收）。代价是**刷新浏览器 = 重建环 =
攒下来的深度全丢**，而真机上就是一边跑一边翻历史。hml 定的是**分成两种寿命**：

- **会话的**：`scope_create` 临时开的，跟连接走，断线即收。现状不变。
- **节点的**：`bind.scope` 里**声明**的那台。声明就是拥有——节点起来它就起来、一直
  攒；浏览器刷新重新接上**同一个环**，深度还在；**节点停、或绑定删了**才释放。

三条随之而来的契约：

1. **身份是 (挂控件的节点, 控件 alias)**，不是 `scope_create` 时发的 `scope_id`
   （[`UiWidget::alias`] 在节点内唯一）。重连按这个键认领；`scope_id` 仍可以当运行期
   句柄，但它不是身份——**别用计时器猜谁拥有它**，那正是"声明胜过推断"要避免的。
2. **节点起来就建，不等浏览器**。等第一个观众才建环，"一直攒"就是假的。
3. **深度在节点启动时就占住**，装不下要**在启动时报错并说明**（不许悄悄缩小深度——
   那是把不正常换成正常）。一个节点上声明了几台示波器就是几份深度：foc-sil 那种五张
   脸 + 两页示波器的图，总量要先算得过来。

改几何（`clock` / `channels` / `sources` / `depth_bytes` / `budget_bytes_per_s`）照旧重建
环、攒的丢掉——那是几何变了，跟寿命是两回事。

**认领本身不许重建**（2026-09-01 真图上抓到过一次，sigflow-core 859b865）：浏览器按
alias 认领时把声明的 setup 原样送回来，几何理应相同。但"相同"是拿**解析出来的
`ScopeSpec`** 比的，里面带着 `srcs[].fs_native`——那是**观测**（口出过帧才知道的率），
不是声明。节点起来时环建在第一帧上，那一刻口的率还没记下来（`fs_native = None`），
于是第一个连上来的浏览器一认领就"几何变了"→ 重建环 → **节点攒的全丢**，而这正是
常驻要避免的事。规矩：**几何只由声明决定**；观测（率、组数一类）参与比较之前必须先
落成真正影响环布局的量（native 下是 `(decim, pairs)`，fixed 下根本不影响），或者在
观测到来时就地更新存着的 spec。

**认领是多份的，setup 是一份**（2a1bbb7 真图验过）：几个页面可以同时认领同一台，
拿到同一个 `scope_id`、都收得到帧（一个页面拉视图，所有认领了的连接都收到同一帧）；
断掉其中一个不影响别人，会话的那台跟着那条连接收掉、常驻的不动。但**旋钮只有一
份**——一个页面改了 setup，另一个页面看到的就是改后的（改几何还会把环重建掉，攒的
丢给所有人）。这是"一台示波器"该有的样子（真机上也只有一台），不是 bug，但 UI 上多
开一页时值得让人知道自己动的是同一台。

**活的 setup 与声明的 setup 是两份，寿命不同**：UI 拨的旋钮即时生效在**引擎**里，
刷新浏览器还在（实测 `refresh_hz` 10 → 20，断线重连仍是 20）；`node.toml` 里
`bind.scope` 的那份是**声明**，只有控件回写才会变（实测此时仍是 10）。所以**节点重启
拿到的是声明的那份**——没回写的旋钮会退回去。这是对的（声明是源头），但别把两者当
成同一份东西看。

**建不起来分两类，按原因分，不按时间分**：`clock`/`sources` 写错、深度合计装不下——
这类永远不会自己好，**立刻喊**；"口还没出第一帧所以不知道帧宽/组数"是常态，**永远
不该喊**，`scope_list` 的 `failed` 里也该说"在等口出第一帧"而不是把按一组算出来的
`vertical[1]: channel 1/v is not among the displayed channels` 摆出来——那句话读起来
就是"你的配置写错了"，会让人去改一个没错的配置。用计时器把两类拖成一类，代价是真错
的那类晚三秒才响。

引擎住在**产源口的那个壳体**（12-a 下所有源同壳体）。绑定的 `node` 指子孙时，声明落在
宿主的 node.toml 里、引擎在子孙的壳体里，谁在启动时去建是壳体侧的事，但"节点起来就
建"这条不变。

### 8.6 给引擎的两条提醒

- `same_geometry` 比的是**写法相等**（`clock`、`channels`、`sources` 逐字段比）：把
  `v` 改写成 `0/v`、把源名从缺省改成显式 `name`，都会多重建一次环。保守，不算错，
  但别在回写绑定时顺手规范化写法。
- 前端的通道键要用 `resolve` 落出来的 `(源槽位, 列 id, 组)`，别拿 `ChanRef` 当键——
  它现在有两层写法相等（省不省源、省不省组），上一轮"触发源下拉显示为空"就是这个。

## 10. 绕圈量：重采样会造出没发生过的过冲（2026-09-01，dex 提，我实测）

角是最常见的"看着像连续量、其实带跳变"的量。`theta_deg` 在 360→0 处是**真跳变**，
不是噪声也不是毛刺。固定时钟把它上采样到别的钟上，要过多相 Kaiser sinc 的 16 抽头
理想插值——理想插值对跳变的回答就是 Gibbs 振铃。

> **判据（2026-09-02，dex 纠的）：看定义里有没有回卷（`fmod` / `atan2`），不是看
> 名字像不像角。** 误差角、相位差、`atan2` 出来的任何东西都是这一族。原来这一节
> 通篇讲"角"，那个措辞会让人按名字筛——**而我自己就是照名字筛的那个人，当场就漏
> 了**：我在信里夸 dex 的 `osc_sync` "选列避开了所有会绕圈的角"，可
> `th_err_edeg` 就在那份选列里，它在 C 核里是
> `fmod(th_exec − th_true + 540·3, 360) − 180`（`foc_sil.c:969`）。名字里没有
> theta、值域贴着 0、看着像个小信号。同一个文件 :839 还有个 `th_err`，回卷到
> ±2048 **counts**——单位更不像角。

### 10.1 实测（假 HOME/9502，sig-gen `ramp` 1 kHz 5 Hz，幅度 ±0.9，系统包 20:56 那版）

| 时钟 | 值域 | 越出 ±0.9 的点 | 最大过冲 |
|---|---|---|---|
| native（不重采样） | [−0.9000, +0.8910] | 0 | 0 |
| fixed 5 kHz（上采 5×） | [−1.1346, +1.1256] | 28 / 1982 | +0.2346 = 跳变的 **13.0%** |
| fixed 20 kHz（上采 20×） | [−1.1346, +1.1256] | 128 / 7987 | +0.2346 = 跳变的 **13.0%** |

**过冲量与上采比无关**（5× 和 20× 一模一样）——它是核的性质，不是比例的性质；上采比
高只是把同一个振铃画得更清楚。换算到 0–360° 的角：一次绕圈会画出 −47° 和 +407°，
屏幕上是每个绕圈处的一对尖角，**看起来像转子真的抖了一下**。

### 10.2 今天的规则

- **固定时钟的选列里不放绕圈量**。绕圈的角在 `native` 上看——不插值、不抽取，角就是角。
- `Mode::Zoh` 只给 `enum`/`bitfield`/`counter`（`resample.rs`）。绕圈量的 `kind` 是
  `Signal`，**拿不到 ZOH**，所以今天没有"声明一下就安全"的写法，只有"别放进去"。
- dex 的 `osc_sync` 就是按这条挑的列，`osc_enc` 因此保留并仍钉 `native`——理由从
  "rotor 没声明率"换成"绕圈的角不能被插值"。**同一个决定，换了个为真的理由**：前一个
  理由现在已经不成立了（rotor 声明了 200 Hz），要是没换，下一个人会照着一个假前提去
  "优化"掉它。
- **"这一列现在会不会绕"和"这一列能不能绕"是两回事，判据按后者写**（dex 提）。
  `th_err_edeg` 闭环下贴着 0、实际不绕，所以**留在选列里安全**；但它**不许上 X-Y
  的轴**——X-Y 的两轴是拿来读几何的，一次失步就把图撕开，而"闭环没失步"是个工况
  假设，不是这一列的性质。安全的是前者，判据得按后者写。

### 10.3 `wrap` 是个真的设计题，但**别只修看得见的那一面**

想根治，列声明里加个"周期量"（`wrap = 360.0`）是对的方向。但它有**三面**，只做第一
面就是这周反复出现的那个毛病——修了自己撞见的那一面，默认那就是全部：

1. **重采样**：解缠 → 插值 → 回卷。这是 dex 撞见的那一面。
2. **每像素列 min/max**：跨绕圈的那一列 min≈0、max≈360，画出一根满量程竖条。native
   上今天也这样，被当成"锯齿画成竖线"接受了；一旦解缠，就得决定这根竖条画哪一种，
   两条路（画竖线 / 按解缠后的连续值画）会给出不同的屏幕。
3. **测量与 AC 耦合**：`mean`/`rms`/视图帧里的 `ac_mean` 对绕圈量无意义——含绕圈的
   一屏，均值恒趋中点，跟转子在哪无关。这一面最容易漏，因为它根本不在重采样那条路上。

**在引擎认这个字段之前，类型层不加它。** 一个声明了没人认的字段比没有更坏：setup 里
写着 `wrap = 360`、屏幕上照样振铃，而写的人以为自己已经处理过了。等 hml 排期，三面
一起做。

### 10.4 触发的时间分辨率 = 触发源那个**源**的采样周期，不是示波器的钟

多源一屏上很容易顺手接一个没验证的推论："两个源都重采样到了 20 kHz 的钟上，所以
它们的因果关系也对齐到了 50 µs"。不对。

ZOH 列的输出是台阶，台阶沿落在**源样本的格子上**（`resample.rs`:
`Mode::Zoh => self.hist[c][i]`，`i` 是源位置的整数部分）。所以拿一个 200 Hz 的枚举
标志列（`z` = "本拍内出现过 Z"）做触发源，触发点只能定位到 **5 ms**——屏幕上 20 kHz
的 100 拍。屏幕的**采样**分辨率是 50 µs，屏幕的**对齐**分辨率是 5 ms，两者差 100 倍。

`osc_sync` 要看的"Z 跳的那一刻电流环怎么动"，因此只精确到 ±1 个 rotor 拍。要真正的
50 µs 因果，得让 `loop` 口自己出一列 Z 标志（20 kHz 那根钟上的），这是口的改动，不是
setup 的改动。**在此之前，这台的读数别当亚毫秒用。**

这条不只对 `wrap` 成立，是多源示波器的通则：**一屏上每一路的时间分辨率是它自己源的，
共同的钟只保证它们画在同一根横轴上，不会把慢的那一路变快。**

## 11. 回写绑定 ≠ 改绑（2026-09-01，hml 撞上，我在真图上复现）

**症状**：示波器页开一会儿就显示"拒"，之后拨任何旋钮（连触发位置也算）都拒，关掉页面
重开就好。同时 `node.log` 里 `常驻示波器已建` 反复出现，`scope_id` 一路往上爬（hml 那张
图 7 分钟内 1→22），攒下的深度一次次清零。

**这是一个 bug，不是两个。** `handle_widget_bind` 无条件 `state.scopes.remove_alias(&alias)`
（`sigflow-core` `shell.rs`:5075），注释写的是"改绑 = 声明变了……几何可能全变了"。前半句
为真，后半句是顺手接上去的推论：**回写绑定的绝大多数情况下几何一个字都没变**——UI 每次
手势结束都会回写一次绑定（600 ms 防抖），拨一下触发位置也算。

真图复现（假 HOME/9502，同一份 setup 原样重绑，几何零改动）：

```
页面打开：UI 认领到 scope_id = 6，攒了 20 拍 → 两秒后 2020 拍
回写绑定（同一份 setup）→ 别名 osc 的 scope_id = 7（换了！），新环 496 拍，旧的 2020 拍没了
UI 手里还攥着旧 id：
  scope_set(6)   → 拒：no scope with id 6
  scope_view(6)  → 拒：示波器 6 没被这条连接认领
  scope_state(6) → 拒：no scope with id 6
```

dex 在另一张图（foc-sil，三台常驻、一台多源）上独立复现，数量级更难看：`osc_loop`
认领到 `scope_id = 1`，两秒攒了 **388552 拍**；把 `scope_list` 拿回来的那份 setup 一个字
不改回写绑定，`scope_id` 变 4，388552 拍全没了，旧号上 `scope_set` / `scope_state` 一律
`no scope with id 1`。两张图、两种 setup、同一条链。

一条因果链把全部症状串起来：拨旋钮 → 600 ms 后回写绑定 → 环被拆、`scope_id` 换新 →
UI 手里的 id 成了死号 → **之后每一次 `scope_set` 都被拒**（拒的不是配置，是号码）→
刷新页面重新认领拿到新号 → 又好了。深度也是这么丢的。

### 11.1 规则

- **回写绑定不是改绑。** 声明的**内容**变了走 `ScopeManager::set()`——它本来就写对了
  （"几何相同就地生效，否则原地重建（**id 不变**）"），这条路上却没被用。
- **只有绑定的目标变了才 `remove_alias`**：换口、换节点、`widget_unbind`、
  `widget_remove`。判据是 `(kind, node, target)` 变没变，不是"有没有人写了一次绑定"。
- **`scope_id` 的寿命不得短于别名的寿命。** 常驻示波器的号码是客户端手里的句柄；壳体
  在客户端不知情的时候换号，等于把它踢下线而不告诉它。真要换（几何变了非重建不可），
  也得让 `set()` 原地重建、号码不变。

### 11.2 客户端侧的两条（UI）

- **被拒的 `scope_set` 不许留下毒。** `commit()` 先 `setup = cfg` 再发，所以一旦有一次
  非法配置进了本地 `setup`，之后**每一次**回写都带着它，条条被拒——"之后干什么都拒、
  刷新就好"也有这一半的功劳（刷新是从声明的那份重新读）。被拒时要回滚到上一份发成功
  的那份。**本地那份 setup 的含义是"我以为引擎手里是这个"；被拒之后它就是假的。**
- **旋钮不许在不知道率的时候瞎写。** `stepSpan()` 的 else 分支（`Oscilloscope.svelte`:392）
  在 `spanSeconds == null || !fsStored` 时写 `span_scans` 并清掉 `span_s`，**不看
  `clock.mode`**；auto 是缺省时钟，而 auto + `span_scans` 是非法的（要按时间推率，拍数
  会绕成循环）。窗口窄（引擎侧实测 `fs_stored` 在建好后 0.4 ms 内就是真值，没有假值
  窗口），但这条路本身就不该存在：**按时钟模式选写哪一种，别按"我现在知不知道率"选。**

### 11.3 这一族

`same_geometry` 我在 §8.6 里已经提醒过"别在回写绑定时顺手规范化写法"，但真出事的地方
比那更前一步：**根本没走到比较那一步就先拆了**。写进文档挡不住这类错，因为写文档的人
和写 `remove_alias` 那一行的人当时想的是两件不同的事（一个想"回写"，一个想"改绑"）。
判据得落在代码里：**能就地生效的路径存在，就不许有一条绕过它的捷径。**

## 12. 通道勾选 = 采集，不是显示（2026-09-02，hml 定）

hml 试用后提的：**通道栏去掉勾选，不只是不画，那一路根本不进环**——跟真机一致。
真机关掉一个通道，让出来的存储和采样率归其余通道，而这一点在我们的控制律里本来
就成立（每通道深度 = 总点数 ÷ 通道数，率跟着每通道深度走）。

### 12.1 一路通道有三种状态，别把后两种混成一种

| 状态 | 在 `channels` | `vertical.on` | 含义 |
|---|---|---|---|
| 关 | 否 | —— | 不采集、不占深度和率；**档位仍留在 `vertical` 里** |
| 采而不画 | 是 | `false` | 进环、占深度；屏上不画 |
| 开 | 是 | `true` | 进环并画 |

中间那一格不是多余的：**重采样时钟（auto / fixed）下触发源必须在 `channels` 里**
（环里只有选中的列，没进环的列不在共同网格上）。所以"我拿 `z` 触发但不想看它"的
写法是**选进 channels + `vertical.on = false`**，不是取消勾选。UI 上取消勾选触发源
那一路时，要么拦住并说清，要么同时把触发源换掉——不能让它变成一台永远不触发的
示波器（那正是"没报错 ≠ 没问题"）。native 的外触发是另一回事，照旧不必进选列。

### 12.2 `vertical` 是**每通道的档位表**，不是"要画的曲线表"

它允许包含此刻不在 `channels` 里的通道：关掉一路再打开，V/div、偏移、耦合还是原来
那份（真机就是这样）。所以 **UI 取消勾选时不要删掉对应的 `vertical`**——删了档位就
丢了，勾回来是一个陌生的档。`measure.channels` 同理：没在采集的通道不出读数，也不
报错。

`ScopeConfig::validate` 因此放开了这条（原来是 `vertical[i]: channel X is not in
channels`），只校验引用本身立得住：源名在、写法合法。

### 12.3 放开的代价：那半张网必须在壳体补上

类型层手里**没有口的列契约**，所以"合法但这轮没勾选"和"根本不存在的列"在这一层
长得一模一样——这正是第七条那族（单个观察与多种状态相容，再怎么盯也分不开）。于是：

- **类型层**：`vertical` / `measure` 的引用只查源名与写法。
- **壳体**（`resolve_scope_spec`）：对着列契约查这一列在不在那个源上，**查不到当场
  报，不许静默跳过**。写错列名不能变成"静默无效"——那比拒绝更难查，因为屏幕上只是
  少了一条线，看起来跟"我把它关了"一模一样。

这不是"多一道校验"，是**同一道校验换了个有信息的层去做**。放开而不补上，等于把
一类错误从"当场报"降级成"永远不说"。

### 12.4 勾选是几何改动——所以停下来之后它不能进引擎

通道数变了 → 每通道深度变了 → 率变了 → **环重建，攒的历史当场没**。

跟"停下来改时基"是同一条：停着的时候，**时基、垂直、勾选都只能是"看"的参数**，
走本地视图，不进引擎。否则你正盯着一屏波形，取消一个勾选就把它删了——而删掉的
恰恰是你停下来想看的那一屏。跑着的时候这三样都可以真进引擎（反正屏在动）。

### 12.5 `scope_describe.available`

去掉勾选之后，光看 `channels` 就不知道还有什么能加回来了，所以 `scope_describe`
多一个 `available: ScopeChannel[] | null`——各源整口展开的通道，不管选没选；解析
不出来（口还没出第一帧）就是 `null`，**不是空表**（空表的意思是"这口真的没有列"，
两者不能混）。它走的是同一条解析路径（把选列清空再 resolve 一次），不是另写一份
展开——这点很重要：另写一份展开就会有两套"这口有哪些列"的答案，迟早分家。

### 12.6 真图验收（2026-09-02，sigflow-core bd65a79，假 HOME/9502，sig-gen 三组 100 kS/s）

放开 `validate` 之后最该核的是**那半张网到底在不在壳体那边**——不在的话，写错列名
就从"当场报"变成"永远不说"：

| 判据 | 结果 |
|---|---|
| ① 采两路、档位表留三路 | 收下（rc=0） |
| ② `vertical` 引用 `iqq`（列契约里没有） | **当场报**：`vertical[2]: 源里没有 iqq 这一列（有：v）——没勾选不算错，写错列名才算` |
| ③ 引用 `3/v`（口只有 3 组，组序越界） | 当场报，同一句 |
| ④ 三路 → 两路 | 每通道深度 3,330,048 → **4,980,736**；`depth_points` = 2 × 4,980,736 |
| ⑤ 认领时的 info | `channels` = 2（选中的）、`available` = 3（整口）、`lifetime` = `node` |

④ 是"让出内存"这件事真的在发生的证据，不是说法。② 的报错把规则写进了错误本身
（"没勾选不算错，写错列名才算"），读到的人不用去翻契约——这正是这一条最容易被误
解的地方。

### 12.7 运行态的寿命：跟引擎，不跟连接，也不进声明

实测（同一台常驻示波器）：

```
按 Stop            → running = false，write_abs 不再涨
断开重连（= 刷新浏览器）→ 还是 false（同一个 id、同一个环）
node.toml           → 没有 running 字段（运行态不进声明）
节点重启            → running = true，又开始攒
```

这是对的，但要说清，因为它跟 §8.5 那句"节点在它就在、一直在攒"有张力：**被 Stop
的常驻示波器不攒**，而按 Stop 的人可能早就关掉浏览器了。三段寿命各归各的：

| 东西 | 活多久 |
|---|---|
| 认领（哪条连接在看） | 一条连接 |
| 运行态（Run / Stop） | 引擎——跨浏览器会话，节点重启回到 Run |
| setup（旋钮） | 声明（`node.toml`），控件回写才变 |

所以"我上周停了它"这件事，在节点重启前对任何人都是不可见的原因。UI 上停着要一直
显示停着（不能只在按下去那一刻提示）。

**更准的说法（core 提炼的）：这不是提示做得够不够，是"常驻"这个词在三段寿命上各
只说了一半。** "节点在它就在、一直在攒"和"被 Stop 的那台不攒"两句都对，合起来会
骗人——后来的人打开页面看到一条不动的波形，最自然的解释是"坏了"，不是"三个月前有
人按了 Stop"。**这份契约里任何只提一段寿命的句子，都会在另外两段上骗人**；写的时
候就得把三段一起说，或者说清自己只在说哪一段。

落地按"会不会被忽略"排（sigflow-core ce0dfa1）：打开就停着且是常驻的 → 波形上方
横幅 + ▶ Run；状态行写"停（手动，**不是这个页面停的**）"，因为横幅会被忽略而读数
行一直在看；**自己按的 Stop 不吵**——那一刻的意图就是停，再解释一遍是噪声。

### 12.8 两条验收纪律

**常驻的东西没有初始态。** core 第二轮验收脚本一上来通道勾选就是禁用的、拖也拖不
动，差点当成新 bug——真因是第一轮停在了 Stop。**验收脚本不能假设自己拿到的是初始
态，得先把状态摆正再断言**；"节点在它就在"的另一面就是"上一轮的手印还在"。

**能拖 ≠ 拖得动。** core 把整行设成 `draggable`，行里那一排按钮把鼠标按下吃掉了，
`dragstart` 根本不触发；`svelte-check` 全绿、单元测试碰不到，跑 playwright 才看见
"拖了等于没拖"。跟我那条"**切得出 ≠ 翻得回**"（§9.5 分段）是同一族：**声明了一个
能力，和这个能力在真实操作顺序下真的能被用到，是两件事**——而只有按真实顺序走一遍
才分得开。

## 13. X-Y 画法（2026-09-02，hml 要看示波器音乐）

`ScopeConfig.display`：

```toml
[widgets.bind.scope.display]
mode = "xy"            # "yt"（缺省）| "xy"
x = { column = "l" }   # ChanRef，mode = "xy" 时必填
y = { column = "r" }
```

### 13.1 它只改画，不改采集

**`display` 不进 `same_geometry`**——在 Y-T 与 X-Y 之间切不该重建环、不该把攒下的
历史清掉。这条有专门的测试钉着（`xy_画法_两轴必填且不能是同一路_但它不进几何`），
理由见 §11 那一族：能就地生效的东西不许走重建那条路。引擎完全不需要认识这个字段，
`resolve_scope_spec` 原样忽略即可。

### 13.2 X-Y 靠"同一拍"成立，而那不是永远为真

一帧里每一路按拍对齐，第 i 个 x 与第 i 个 y 是同一拍——**但这只在视图发原始样本时
成立**。视图的判据是 `span < 2 × px && span <= 65536`（sigflow-core
`scope/view.rs`：`RAW_BELOW_SCANS_PER_PX = 2.0`、`RAW_MAX_SCANS = 65536`）；超过就
退化成每像素列的 `(min, max)`，那时 `x[i]` 与 `y[i]` 是**各自窗口里的极值**，压根不
是同一拍，连出来的不是轨迹而是一团。

所以 X-Y 要把一屏收短：px = 1024 时 `span < 2048` 拍，48 kHz 的音频算下来一屏
**20–40 ms**。这不是"长了会糊"的程度问题，是**过了那条线 X-Y 的前提就不成立了**。

**越线之后不画**（sigflow-core c2595de，core 定的，比"提示一下"强）：只给一句话和
一个「调到能画」。编出来的图看着像信号，人会当成自己调错了参数去追——**错的图会支
人去反方向**，跟"把后果说成显性的那种比说错更坏"是同一笔账。

**判据用帧自己的 `kind`，不要重算 span 阈值**：阈值要跟 `RAW_BELOW_SCANS_PER_PX`
和 px 对齐，那就是同一个数写两份，两份数迟早分家（同 §12.5 `available` 要走同一条
解析路径的理由）。帧里已经写着它是哪一种：`MinMax = 0`、`Raw = 1`、`RawPairs = 2`
（`scope/wire.rs`）。**判据是 `kind != 0`，不是 `kind == 1`**——`RawPairs` 是峰值
存储下**每拍一对**，配对照样成立；照 `kind == 1` 写，峰值存储的环上 X-Y 会无故空白，
而那种环恰恰是超预算时才出现的，最不容易被复现到。上面那段 span 的算式是**讲道理
用的**（说清前提为什么会失效），不是给实现抄的判据。

### 13.3 两轴不能是同一路——而"是不是同一路"不能用 `==` 判

`ColumnRef` 的 `PartialEq` 是**写法相等**（§4 那条老账）：单组口上 `{ column = "l" }`
与 `{ column = "l", group = 0 }` 指着同一路却判不等。所以 validate 用的是
`ColumnRef::may_be_same`——**问"有没有可能是同一路"，重合就拒，宁可保守**。按下标
和按列名混着写（`@0` vs `l`）这一层分不开，跟 §12.3 一样交给壳体：它有列契约，落到
具体通道之后再判。

### 13.4 X-Y 下没有余辉（已知缺口）

密度图是"每通道对时间"的网格（`T × A`），X-Y 用不上——所以矢量画现在是单帧线条、
没有拖影。**而拖影恰恰是示波器音乐观感的一半**（真机的余辉就是它好看的原因）。要做
得在 X-Y 平面上另开一张累积网格，或者前端 FBO 累积 + 衰减。hml 还没要，先记着，
别让人以为"画出来了 = 做完了"。

### 13.5 用它的例子：Primer

hml 要的例子放 `example/`：播 **Primer**（BUS ERROR Collective：DJ_Level_3 与
Marv1994；2025-04-20 发布，Revision 2025 Wild **第一名 + Crowd Favorite**，
Meteoriks 2026 New Talent）。它是**示波器音乐**——两路音频驱动 X-Y，屏上是画。

**不把作品文件提交进仓**（core 提的，对）：那是别人的作品，例子里只放"怎么拿"和怎么
接线，README 指向官方发布页（Demozoo `productions/371249`、pouët `prod.php?which=103998`、
scene.org 的官方下载）。**官方发布的是 FLAC，不是 WAV**，所以例子要么带一句
`ffmpeg -i primer.flac primer.wav`，要么源插件自己解 FLAC——WAV 解析零依赖，FLAC 不是，
先走 WAV + 一句转换。

接线：源插件把 stereo 文件播成 2 列的口（`l` / `r`），`declared_rate_hz` = 文件采样率；
时钟 `native`（原样进环，X-Y 画的才是真轨迹）；两路都在 `channels` 里、`vertical.on = true`，
**两路 V/div 取同一个值**（两轴同档才是圆不是椭圆）；一屏 20–40 ms（见 §13.2）。

### 13.6 旧壳体会**静默吃掉**它不认识的字段（我实测，比 core 说的更宽）

core 提的是"`display` 还没进 main，旧壳体反序列化会忽略它，所以存不住"。我拿**当前
装着的**那支壳体（`/usr/bin/sigflow-shell`）量了，事实比这句更宽：

```
node.toml 里手写 [widgets.bind.scope.display] → 起节点，磁盘上还在
sigflow-cli param set freq_hz 777              ← 跟这个控件毫无关系的一次改动
→ display 段没了（存盘时按它认识的形状重写了整个文件）
```

**触发存盘的事情可以跟那个字段毫无关系。** 所以准确的说法不是"X-Y 存不住"，是
**"node.toml 只要经过一个旧壳体存一次盘，它不认识的字段就永久没了"**——而且这不是
示波器特有的，是 serde 往返的一般性质：未知键读进来就丢，任何一次 `save_config` 都
按内存里那份重写整个文件。

**什么时候真会咬到**：webui 是编进壳体二进制的，所以"新 UI + 旧壳体"这种组合不会
自己出现。真实的路径是**部署脚本**——脚本里写了新字段的 scope TOML，发到一台装着旧
包的机器上，第一次存盘就没了，而脚本和文件看起来都对。dex 的 example 脚本正是这么
写 setup 的。

**这一族我自己犯过一次**：§9.4 的 `ScopeSetup::Broken` 保住了**读不动**的 setup 的
原文，我当时的结论是"老 setup 不许拖住节点起不来"——那解决的是我撞见的那一面。
**旁边这一面（读得动、但有不认识的键）会静默丢数据，我压根没查。**

**修法的形状**（没做，等真有混版本部署的需要再说）：`ScopeConfig` 上挂一个
`#[serde(flatten)] extra: BTreeMap<String, Value>` 把不认识的键原样带过去，往返就
无损了。代价是拼错的键会落进 `extra` 而不是报错——不过今天本来就不报错（serde 缺省
就是忽略），所以这一步只赚不亏；真要更好，是**存盘时对 `extra` 里的键出一条 warn**。

**眼下的操作规则**：升级要么全升，要么别让新字段进老机器的 node.toml。

### 13.7 改契约的纪律：**语义要变就换键名**

老配置遇上新代码（或者反过来），只有三扇门：

| 进法 | 会怎样 | 有没有网 |
|---|---|---|
| **读不动**（形状对不上） | 解析失败 | 有：`ScopeSetup::Broken` 保住原文，节点照常起（§9.4） |
| **读得动但不全**（有不认识的键） | 存盘时静默删掉 | 有：读的时候当场点名（sigflow-core f21fedd，§13.6） |
| **读得动、键也不丢、意思变了** | 照读、照跑、结果差十倍 | **没有，而且结构上补不了** |

第三扇门补不了：文件里没有版本号，值也完全合法，两边各自看着都正常——正是
[[judging-in-this-project]] 第七条那族（单个观察与多种状态相容）的极端形式。
举个具体的：`span_scans` 哪天要是从"整屏拍数"改成"每格拍数"，老配置照读照跑、
数值差 10 倍，**没有任何一层会响**。

所以唯一的挡法是**不要那么干**：

> **一个键的语义变了，就换个键名。**

换名之后它退化成第一扇门（读不动）或第二扇门（不认识的键）——那两扇我们都有网。
我们已经走运过一次：`depth_bytes` → `depth.points` 是**换了键名**的，所以变成了
"读不动"，当场就露；要是当时偷懒把 `depth_bytes` 的含义直接改成点数，今天没有任何
一处会告诉我们哪些机器上的深度小了 4 倍。

**换键名挡不住的那一种：一个词悄悄多了个所指**（2026-09-02，core 提炼，§9.7 是实例）。

上面三扇门管的都是**键**——键读不动、键不认识、键的语义变了。还有一种住在**术语**
里，换键名一点用没有：

> `记录` 原本指"触发扫描器出的那些"。§9.5 之后它多了一个所指——自由跑按屏长切出来
> 的也是记录。于是 `AcqMode::Persist` 那句"**每条记录**都进余辉密度图"**适用面跟着
> 变了，而那句话一个字没动**。

没有任何一处需要修改，因而**也没有任何一处会提醒你**。这比第三扇门更隐蔽：那扇门至
少还有"我在改这个键的语义"这个自觉时刻，而给一个词加所指的时候，人想的是"我加了个
功能"，压根不会想到自己动了别处句子的范围。

**唯一的挡法：给一个词加所指时，把用到这个词的地方数一遍。** §9.7 那次漏的就是这一
步——加了第二个记录来源，只接上了当时想着的那个消费者（分段翻页），没接上另一个
（密度累加）。

配套的两条（core 提炼的）：

- **判据要从被判的那个操作本身长出来，不要在旁边另建一套。** 这一轮出现了三次：
  `available` 走同一条解析路径（不另写一份展开）、X-Y 用帧自己的 `kind`（不重算
  span 阈值）、丢键告警比"存盘真会写下去的那份"（不估计）。为什么它总奏效：另建
  的那套是**当时的理解的快照**，而被判的操作会继续演进——**分家不需要谁犯错，只
  需要时间**。所以这不是"更严谨"，是免掉一整类将来才会发生的错。
- **判据按穷举写，别按"我见过的那一种"写**（见 §13.2 的 `kind != 0`）：漏掉的那
  一支永远轮不到你亲眼看见。
